# Screenshot guide for project submission

Use actual screenshots from the browser after opening `index.html` with VS Code Live Server. Do not use AI-generated mockups as evidence of the implemented website.

Suggested captures:

| Suggested filename | What to capture |
|---|---|
| `homepage-hero.png` | Full desktop homepage hero and navigation |
| `homepage-sections.png` | Homepage categories, featured places or city panels |
| `explore-directory.png` | Search, filters and first results on Explore |
| `delhi-overview.png` | Delhi hero, nine-zone index and five quick-area shortcuts |
| `delhi-results.png` | Delhi venue directory and filter controls |
| `tricity-overview.png` | Chandigarh Tricity hero, four town panels and five quick-area shortcuts |
| `tricity-results.png` | Tricity venue directory and filter controls |
| `experience-detail.png` | One real venue opened from a directory card |
| `about-page.png` | About hero and story section |
| `contact-page.png` | Suggestion form and frontend-only notice |
| `mobile-home.png` | Homepage at a narrow mobile viewport |
| `mobile-directory.png` | Explore page at a narrow mobile viewport |

To capture a page, use the browser's built-in screenshot function or Windows Snipping Tool. Keep the browser URL bar visible where the screenshot is intended to demonstrate which page is open. Test at least one mobile viewport and, ideally, one physical phone before submission.
